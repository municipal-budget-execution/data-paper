# CLAUDE.md — Instructions for Claude Code

This file provides guidance for Claude when working in this repository.

## Project overview

Replication package for the paper **"MiDES: New Data and Facts from Local Procurement and Budget Execution in Brazil"** (World Bank Economic Review, accepted).

The goal is reproducibility: anyone with access to the data should be able to run the code and regenerate every table and figure in the paper exactly.

## Repository layout

```
MiDES-data-paper-repository/
├── CLAUDE.md                  ← this file
├── README.md                  ← human-readable overview

│   │   ├── API_ComprasDados/
│   │   └── queries/
│   ├── analysis/              ← one R script per figure/table group

└── docs/
```

Data files are stored outside the repo (Dropbox) and are **never committed to git**.

**All analysis code is R.** There is no Python or Jupyter dependency. Original notebooks are in `code/archive/`.

## Entry point

```bash
bash main.sh               # use existing processed data, regenerate all outputs
bash main.sh --redownload  # re-fetch raw data from BigQuery, then regenerate
```

`--redownload` requires a configured Google Cloud project and `basedosdados` credentials. Default is false — processed input CSVs are provided with the package.

## Paths convention

All path configuration lives in `code/utils/paths.R`. Never hardcode paths in analysis scripts. Paths are set based on `Sys.getenv("USER")`.

Key directories:
- **Raw input**: `{dropbox_dir}/Data/Raw/` → `input` — truly raw files only: shapefiles, IBGE XLS, `ipca_anual.csv`, `region.csv`, `comprasdados/`
- **BigQuery extracts**: `{dropbox_dir}/Data/Intermediate/BigQuery/` → `bigquery` — all SQL/BigQuery-originated CSVs, re-generated by `ingest_bigquery.R`
- **Other intermediate**: `{dropbox_dir}/Data/Intermediate/` → `intermediate` — pre-built files not regenerated by `--redownload` (Transparency_Federal_2021, mayors.dta, FINBRA files, etc.)
- **Figures output**: `output/figures/` (relative to repo root, cleared by `main.sh`) → `graph_output`
- **Tables output**: `output/tables/` (relative to repo root, cleared by `main.sh`) → `table_output`

**Important**: The paper's tex reads home bias regression tables via `\input{figures/...}`, so `tab_regressions_home_bias.R` and `fig_home_bias_federal.R` write their `.tex` outputs to `graph_output` (`output/figures/`), not `table_output`.

## Coding conventions

- **All code is R.** No Python.
- Data manipulation: `data.table` (preferred) or `dplyr`
- Figures: `ggplot2` with the shared theme from `code/utils/set_theme_ggplots.R`
- Maps: `sf` + `ggplot2`
- Tables: `modelsummary` or `kableExtra`
- Package loading: `pacman::p_load()` in `code/utils/packages.R`
- Each analysis script is self-contained: sources `code/utils/paths.R`, loads its own data, saves outputs. No global state from other scripts.

## What NOT to do

- Do not commit data files (csv, parquet, dta, xlsx). They live in Dropbox.
- Do not commit output files (figures, tables). They are generated by `main.sh`.
- Do not change the paper tex files — they live in `../MiDES-data-paper-replication/`.
- Do not alter the substance of any analysis. Refactoring is structural only.
- Do not introduce Python. All code must be R.

## Verification rule

After any refactoring, run the affected script end-to-end and visually compare outputs to those in `../MiDES-data-paper-replication/WBER_Submission/FinalSubmission/figures/` and `tables/`. Results must be byte-identical or visually identical.

## Git discipline

- Work on branch `refactor/clean-structure`.
- Make atomic commits: one logical change per commit.
- Commit message style: `refactor: <what changed>` or `chore: <what changed>`.
- Never commit to `main` directly.
